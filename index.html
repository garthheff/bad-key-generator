A brief audit of our terrible decisions

Why this is terrible.

A private key is supposed to be hard to guess. Ours is hard to take seriously. Here's where the wheels fall off.

FAILURE 01 / THE MATH

Eight guesses. That's the attack.

Anyone who knows the list can try every possible value in at most eight guesses. With equal chances, the first guess already has a 1-in-8 shot. No supercomputer required. A short to-do list will do.

FAILURE 02 / THE RANDOMNESS

Shuffle the deck. Still eight cards.

Clicking again only picks another value from the same tiny set. Math.random() isn't a cryptographically secure generator, and even a better picker couldn't rescue these eight possibilities. More clicks don't make a bigger secret.

FAILURE 03 / THE CONSEQUENCES

The padlock can't save you.

If a real signing key can be guessed, an attacker can forge signatures. For a certificate authority, that can mean forged certificates that appear to come from a trusted issuer. A reassuring badge is a poor substitute for an unguessable key.

In everyday language: imagine your front-door key.

You buy a new lock, but the shop sells only eight different keys. A burglar gets all eight and tries them one by one. One of them will open your door. Picking a different key from the same shop doesn't solve the problem. the burglar already has that one too.

Now imagine the lock comes with a shiny “VERY SAFE” sticker. It still opens with one of those eight keys. The sticker doesn't make the lock safer.

That's this website: it picks from just eight numbers, so someone else can easily guess yours. A real digital key needs so many possibilities that trying them all is impractical. Ours is a joke lock with the spare keys left on the doormat.

Longer-looking isn't stronger. Adding zeros, printing a number in hex, or wrapping it in a fancy certificate doesn't increase the number of possible secrets. This page generates toy numbers only. Never use them for real keys.

Why was this page made?

This page started as a joke about a weak-key incident involving a certificate authority, a company trusted to issue digital certificates that help websites prove who they are. It takes the idea to a ridiculous extreme: a “private key generator” with only eight possible answers.

The point is simple: a secret that is easy to guess cannot keep much safe, even when it comes with an official-looking certificate. The company-themed ratings poke fun at other historical security mistakes, with sources in “Security-rating jokes: the receipts”.

It's a little comedy with a useful lesson: looking secure and being secure are very different things. These are toy numbers for a joke, never real keys.

Is any of this actually secure?

No. This is a joke. The number picker uses Math.random() and can only choose from eight public values. It does not create cryptographic keys, certificates, or anything suitable for protecting data.

Where does my extremely bad key go?

Nowhere. Everything runs in this page, with no dependencies, backend, tracking, cookies, or browser storage. Copying writes only the displayed joke number to your clipboard, if your browser permits it.

Why “at most 3 bits”?

Eight equally likely possibilities would contain log₂(8) = 3 bits of entropy. That's the ceiling for this list, not a claim about the quality of the number picker. Repeated values are possible.
